# Devices and forks (2026-11-28)

One project, many phones. This file maps every known OneiOS device fork: what runs where,
what already flowed back into `main`, and what is still fork-only. Status as of 2026-11-28;
fork contents move fast and this file will go stale — the dates say when it was true.

Our own target stays the rooted Galaxy S24 Ultra (the owner's SM-S928B, SM8650; every SM-S928 model, the Canadian
SM-S928W too, takes the same path: `docs/hardware.md` 7h, "The S24 Ultra's models"); everything below is
judged by what it teaches `main` or what runs on more phones without breaking the S24 Ultra.

## The S26 Ultra pass of 2026-11-23 (`port-sm8850-s26`)

`YMGPwcca/OneiOS` (6 branches, newest `feat/sm8850-full-bridges-takeover` of 2026-11-22: 616 own commits since
2026-11-15) and its app fork `YMGPwcca/OneOS` (`feat/sm8850-full-bridges-takeover`: 165 commits over our `oneios`, 46
behind) read again for what an S26 Ultra user needs that `main` and the OneOS fork lack. The sorted list, with every
reason, is [s26.md](s26.md). In short:

- **Taken into the OneOS fork** (branch `sm8850-support`, on `s928w-support`): the Gradle fixes `ab28274` and
  `590b4a6` (every build) and their docs; the shmem restore of an early return (part of `403d8b4`, every phone); the
  S26 Ultra **warned** with what is known (app gate and the switch's own check), not refused.
- **Taken into `main`** (this branch): the S26 row matches by codename `m3q` and platform `canoe` too, `verify-host.sh`
  takes SM-S948, the SM8850 CPU and S Pen stand-ins, the host record `profiles/host-galaxy-s26-ultra-sm8850.toml`,
  the port record `docs/s26.md`.
- **Not taken**: the fork's S26 refusal (against the owner's 2026-11-16 rule), its watchdog rewrite (it would refuse
  the switch on an S24 Ultra build without the watchdog sysfs attributes, and on every other phone), its
  gpio-keys/pmic_resin key rule (it refuses phones with other key drivers), Gate A before the early return (a restart
  of a One UI that never stopped), the Framework-takeover experiment (exclusive touch, cpufreq caps, a restart as the
  way back), the Python tools, the GPU/display refactor, their docs.

## What the forks already made better (in `main`)

- **The SoC thermal rule on the phone's own trips** (YumikoHayamato S25 Ultra, 2026-11-22): the kernel's trips are read
  and logged on every phone; the SM8750 rows raise the rule to them and read the lowest of 3 readings, so a junction
  spike at the kernel's first trip no longer puts iOS in TRAPPING. Opt-in: the S24 Ultra is unchanged.
- **udmabuf ENOMEM fallback** (YumikoHayamato S25 Ultra): smaller udmabufs when a pre-6.10 kernel cannot find
  contiguous memory for the page array. Every phone; acts only on a refusal.
- **No silent 2D-only runtime** (YumikoHayamato): `runtime/build.sh` refuses a stage without the GPU renderer.
- **`boot-args-add`** (YumikoHayamato): a profile adds a boot argument without replacing the defaults.
- **Base S25 stand-ins** (NoNameBuilder): battery, thermistor, panel and Adreno 830 shapes in the host tests.
- **Oryon CPU topology** (s25ver): Qualcomm implementer `0x51` is never E; all-performance hosts lend the slowest
  cores as E vCPUs. A latent wrong-topology bug on every big-only SoC, not just the S25; S24 behavior unchanged.
- **Multi-phone backend tests** (YMGPwcca via the hw-backend merge): samsung vs treble backends against stand-in
  sysfs/binderfs, the harness every new phone reuses.
- **Native haptics impact path** (YMGPwcca, merged 2026-11-21 — guest→HAL delivery NOT physically

- **Phone probe tooling** (`tools/probe/s25-probe.sh`): read-only fact-gatherer; the first step of any new port.
- **Adreno 830 fence default** (denis S25 Ultra): `WAITTIMESTAMP_CTXTID` everywhere until the FENCE path is

## How one tree supports many phones (the pattern)

- **Host device table** (2026-11-21, `host-device-detect`): xnuhost detects the host phone at start (`ro.product.model`, `ro.product.device`, `ro.board.platform`, `ro.soc.model`, `ro.soc.manufacturer`; soc0 and the device tree as fallbacks) and takes its defaults from one table, `runtime/bridges/hw/host_device.rs`: S24 Ultra (none, today's), S25 Ultra (`ONEIOS_THERMAL_SOC_TRIPS=1`, `ONEIOS_THERMAL_SOC_SAMPLES=3` since 2026-11-22), S25 (`panel-fallback=1080x2340@120`, `corner-radius=34`, built-in side keys, `hw-backend-thermal=treble` + fallback, and the same thermal rule), S26 Ultra (`ONEIOS_BRIGHT_MAX=2300`), S26 Snapdragon (`panel-fallback=1080x2340@120`, `ONEIOS_BRIGHT_MAX=2300`, SM8850 thermal rule), S26 Exynos (`gpu=2d`, `panel-fallback=1080x2340@120`), A56 (`gpu=auto` since 2026-11-24, `gpu=2d` before; `panel-fallback=1080x2340@120`). The command line and the image set win over it; `host-device=none` turns it off, `host-device=NAME` forces a row. A port adds a table row (existing options only) plus its record, instead of a fork. `docs/hardware.md` 7h.
- **Backends, not forks**: `runtime/bridges/hw` (`hw-backend=samsung|treble`, per-bridge overrides) plus the
  stand-in tests above. A new phone starts by proving its backend against fakes, not by forking the repo.
- **The runtime is Rust since 2026-11-23** ([runtime/RUST.md](../runtime/RUST.md)): a fork branched before that
  carries the C runtime, whose files are gone here. Its runtime changes come over as changes to the Rust module that
  replaced the C file (one C file became one module: `topology.c` is `runtime/bridges/cpu/topology.rs`, `gpu3d_kgsl.c`
  is `runtime/xnuhost/src/gpu3d_kgsl.rs`, ...), with the C tests' cases as Rust tests. Kernel patches, `drivers/` and
  `userland/` are still C and merge as before.
- **Per-device records**: `docs/s25.md` is the template (F/I/U-marked device table, verdict table, probe→decision
  matrix). A port lands as a record plus its profile/config, not as a parallel universe.
- **Per-device config**: `userland/config/device-iphone18,2.toml` is the guest-side pattern; the host side follows
  the same shape as backends grow.
- **What a new port still needs each time**: its hardware map first (`oneios-tool phone hw`, read only, since
  2026-11-28; `tools/probe/s25-probe.sh`), then panel mode/refresh (display helper XHDP report), input/evdev
  capabilities, sensor/HAL paths (backend stand-ins first), GPU backend notes (AGX gate pattern in `docs/gpu.md`),
  kernel notes only where the SoC differs (the Oryon rule is the template: describe, test, keep old phones unchanged).
